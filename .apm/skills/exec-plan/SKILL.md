# Exec Plan

実装タスクを「計画作成 → 実装 → レビュー → 修正」のループで進めるためのスキル。オーケストレーションはせず、計画書の作成・更新・完了処理だけを責務とする。実装はメインループで行い、レビューは既存のレビュースキルに委ねる。

## 前提

要件が曖昧なうちは計画を書かない。先に `/grilling`（または `/grill-with-docs`）で要件を固めてから、その結果をこのスキルで計画に落とす。

## ワークフロー

### 1. 計画作成

- `docs/exec-plans/template.md` を読み、`docs/exec-plans/active/YYYYMMDD-<slug>.md` を作成する
- grilling や会話で決めた設計判断は Decision Log に `YYYY-MM-DD: <判断と理由>` の形式で記録する。問答の結果を揮発させない
- Steps は `- [ ]` のチェックリスト形式で、「〇〇ファイルに〇〇を追加する」レベルの具体性で書く。10 個以下を目安にし、多い場合はグループ化する
- Acceptance Criteria は「〇〇のとき〇〇になる」と検証可能な形で書く
- 書き出したら Steps をユーザーに提示して承認を得る。承認まで修正を繰り返す

### 2. 実装

- Status を `in-progress` に更新し、Steps を上から順に実行する
- 完了したステップは `- [ ]` を `- [x]` に変える
- 実装中に計画と実態が食い違ったら Decision Log に記録して計画を更新する。食い違ったまま放置しない
- 変更は Scope 内に収める。Scope 外の変更が必要になったらユーザーに確認する

### 3. レビューと修正

- 実装が終わったら `code-reviewer` スキルでレビューする
- 指摘はユーザーに提示して修正対象を確認し、修正 → 再レビューを必要なだけ繰り返す

### 4. 完了

- Validation を実施結果で埋める
- Status を `completed` に更新し、ファイルを `docs/exec-plans/completed/` へ移動する
