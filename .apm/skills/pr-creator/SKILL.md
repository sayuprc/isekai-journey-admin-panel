# PR 作成スキル

GitHub の PR を `gh` コマンドで作成するための手順です。タイトル・本文は日本語、テンプレートは `.github/pull_request_template.md` を使います。

## 前提

- `gh` コマンドが利用可能で、認証済みであること
- リポジトリのルートディレクトリで作業していること

## ワークフロー

### 1. 現在の状態を把握

並列で以下を実行して状況を理解します。

```sh
git status
git diff
git diff --staged
git log --oneline -20
git branch --show-current
```

確認事項：

- 現在のブランチ（main/master/dev など主要ブランチに直接 PR を作ろうとしていないか）
- ステージ済み・未ステージの差分の中身
- 未追跡ファイルが何か
- 直近のコミット履歴

### 2. ベースブランチを判定

作業ブランチの「分岐元」を特定します。これは PR の `--base` に渡す値です。

```sh
# 候補ブランチ（リポジトリに存在するもの）の merge-base を比較
for b in dev main master develop; do
  if git rev-parse --verify --quiet "origin/$b" > /dev/null; then
    mb=$(git merge-base "origin/$b" HEAD 2>/dev/null)
    cnt=$(git rev-list --count "$mb..HEAD" 2>/dev/null)
    echo "$b $cnt $mb"
  fi
done
```

判定方針：

- 候補のうち、`merge-base..HEAD` のコミット数が最小のブランチが分岐元の有力候補
- ただし複数候補で差が小さい場合や、判定に自信が持てない場合は **必ずユーザーに確認** する
- このリポジトリの慣例として `dev` がデフォルトであることが多いが、推測で進めずに不明なら確認すること

### 3. PR に含める差分を選別

「関係のない差分は含めない」がこのスキルの肝です。以下の方針で判断：

- 既にコミット済みでブランチに含まれている差分は、原則すべて PR の内容として扱う
- 未コミットの差分は、内容を読んで「今回の作業の一部か」「無関係なローカル作業か」を判断する
  - 無関係（例：ローカル検証用の `dump.sql`、エディタ設定、別テーマの変更）→ コミットしない、PR に含めない
  - 関係あり → 適切な粒度でコミットしてから push する
- 判断に迷う差分があれば、ファイル名と要旨を提示してユーザーに確認する
- 機密情報を含むファイル（`.env`, 認証情報, ダンプ等）は絶対にコミットしない

未コミット差分をコミットする場合は `git add <具体的なパス>` で個別指定する。`git add -A` や `git add .` は使わない。

### 4. リモートに push

```sh
git push -u origin <current-branch>
```

既に upstream が設定されていれば `git push` のみで可。

### 5. PR タイトルと本文を作成

タイトル：

- 日本語で簡潔に（70 文字以内）
- ブランチ上の全コミット（直近 1 件ではない）を踏まえて、変更全体を表す内容にする
- 主要コミットのメッセージ傾向に揃える（例：「〜を追加」「〜を修正」「〜をリファクタリング」）

本文：`.github/pull_request_template.md` の構造を厳守。

```markdown
## 概要

<この PR が何を目的としているかを 1〜3 行で>

## やったこと

- <具体的な変更を箇条書きで>
- <粒度はレビュアーが流れを追える程度>

## やってないこと

- <スコープ外として意図的に対応しなかったこと>
- <該当なしなら「特になし」と書く>

## 関連

- <関連 ISSUE・PR があればリンク。なければ「特になし」>
```

書き方の指針：

- 「やったこと」は実装の「何を」ではなく、レビュアーが理解すべき変更のまとまりを書く
- コミットメッセージや会話履歴から関連 ISSUE 番号（`#123` 等）が判明する場合は「関連」に記載
- HTML コメント (`<!-- ... -->`) はテンプレから取り除いて構わない

### 6. PR を作成

タイトル・本文の体裁を保つため、本文は HEREDOC で渡す。

```sh
gh pr create \
  --base <base-branch> \
  --title "<日本語タイトル>" \
  --body "$(cat <<'EOF'
## 概要

...

## やったこと

- ...

## やってないこと

- ...

## 関連

- ...
EOF
)"
```

作成後は出力された PR の URL をユーザーに伝えます。

## 注意事項

- ユーザーから明示の指示がない限り、`--draft` は付けない
- `--no-verify` などフックを無効化するオプションは使わない
- main/master のような保護ブランチを `--base` に指定するときは、本当にそれで良いか一度確認する
- PR 作成前に `git status` で意図しないファイルが入っていないか最終チェックする
