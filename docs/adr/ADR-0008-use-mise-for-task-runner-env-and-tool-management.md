# タスクランナー・環境変数・ツール管理に mise を採用する

## Context

プロジェクトでは複数のコンポーネント（API、管理画面、クライアント）が存在し、それぞれで異なるランタイムバージョンの管理が必要になる。
また、開発作業を標準化するためのタスクランナーも必要だった。

従来の方法（`.nvmrc` + `Makefile` など）はツールが分散していて管理が煩雑になりやすい。
mise は「ランタイムバージョン管理・環境変数管理・タスクランナー」を1つのツールで統括できるため、採用することにした。

なお、プロジェクト固有の機密情報や環境差分は従来通り各コンポーネントの `.env` ファイルで管理する。
mise の環境変数管理はプロジェクト横断で共通利用できる値に限定する。

## Decision

mise を次の用途で統一的に使用する。

- **ツール管理**：Node.js などランタイムのバージョンを `mise.toml` で宣言し、`mise install` で揃える
- **環境変数管理**：プロジェクト横断で共通利用できる環境変数を `mise.toml` の `[env]` セクションで定義する
- **タスクランナー**：`mise.toml` の `[tasks]` セクションにタスクを定義し、`mise run <task>` で実行する

## Consequences

### Positive

- ツール・タスクの定義を `mise.toml` に集約でき、設定の見通しがよい
- `mise install` だけで開発に必要なランタイムが揃う
- タスクに依存関係（`depends` / `depends_post`）を定義でき、実行順序を明示的に管理できる

### Negative

- チームメンバー全員が mise のインストールと使い方を覚える必要がある
- mise に不慣れなメンバーはオンボーディングコストが発生する
