# Core Beliefs

この文書は、ADR より軽く、それでも将来の変更判断に効く原則をまとめるためのものです。

## 1. 地図を先に置く

最初に読む文書は短い地図であるべきです。README や `ARCHITECTURE.md` は入口に徹し、詳細は下位文書へ分けます。

## 2. 知識はリポジトリに残す

会話、レビューコメントだけに存在する判断は、将来の実装者から見えません。繰り返し参照される判断は `docs/`、ADR、instructions に昇格させます。

## 3. 契約と生成物の境界を守る

API の Source of Truth は TypeSpec です。生成物を直接直すのではなく、生成元を更新して再生成します。

## 4. 境界を明確にして自律性を上げる

サーバーは ADOP の層を守り、フロントエンドはページ、コンポーネント、BFF、生成クライアントの責務を分けます。どこを触るべきかが明確なほど、変更は速く安全になります。

## 5. 検証は近いところから行う

大きなフルテストより先に、変更箇所に最も近い lint、型検査、単体テスト、生成チェックを回します。安いフィードバックループを優先します。

## 6. 繰り返し出るレビューは仕組みに移す

同じ指摘が何度も出るなら、会話で毎回説明するのではなく、文書、lint、hook、生成フローに移します。
