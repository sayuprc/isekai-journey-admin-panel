# Song Media Release Admin Phase 1

## Summary

第1回ローンチでは、既存の楽曲管理基盤を前提に、`admin` で楽曲、リリース、公式 `Media` を登録・編集・閲覧できる状態を作る。差別化の中心は、文字情報だけでなく、楽曲とリリース、さらに公式メディアの結び付きを運用できることに置く

## Current Status

- 2026-05-06 時点で、`Media` の Phase 1 実装は進んでいる
- `Song` 作成 / 編集 / 詳細で `Media` を扱う導線は実装済み
- 現行実装では、メディアの意味分類は `SongMediaType` ではなく `Media.format` で表現する
- `SongMediaLink` は `song_id / media_id / order_no` を中心に持ち、楽曲ごとの責務は関連付けと表示順に絞る
- `Event` はまだ未実装であり、この資料内の `Event` 記述は将来構想として扱う

## Users / Actors

- 管理画面の管理者
  - 現時点では主に 1 人で運用する想定
- 将来の閲覧者
  - 今回は直接の利用者ではないが、第1回ローンチで蓄積したデータの影響を受ける

## Problem

既存の楽曲、タグ、`Person` 基盤はあるが、プロダクトとしての差別化を担う `Media` 運用と、ディスコグラフィーの軸になる `Release` 運用が不足している。文字ベースの情報サイトや動画ベースのサイトはすでに存在するため、楽曲情報をリリースと公式メディアまで含めて一体で管理し、後の `viewer` や出来事機能につながるデータ基盤を `admin` で先に成立させる必要がある

## Goals

- `admin` で楽曲の基本情報を安定して登録 / 編集 / 閲覧できる
- `admin` でリリースの基本情報を安定して登録 / 編集 / 閲覧できる
- 楽曲タグと `Person` 関連付けを既存基盤の上で運用できる
- 楽曲とリリースの関連付けを運用できる
- 楽曲に対して公式 `Media` を登録し、関連付け、表示順を管理できる
- 楽曲作成 / 編集画面で、既存 `Media` の選択と新規 `Media` 作成の両方を扱える
- 楽曲詳細で、既存表示情報に加えて関連 `Media` を確認できる

## Non-Goals

- `viewer` の詳細な情報設計やデザイン確定
- `Media` 単独一覧ページの提供
- 非公式 `Media` の取り扱い
- 画像メディア対応
- 複雑なリリース版管理
- 出来事 CRUD
- 場所管理
- 楽曲がどの出来事で披露されたかの管理
- 歌唱者を楽曲本体属性として持つこと

## Affected Surfaces

- `src/contracts`
- `src/server`
- `src/admin`

## Core Flow

1. 管理者がリリースまたは楽曲作成 / 編集画面を開く
2. リリースの基本情報と収録楽曲、または楽曲の基本情報、タグ、`Person` 関連を入力する
3. 楽曲に対して関連リリースと `Media` を紐づける
4. 関連付けた `Media` の表示順と、リリース内の曲順を調整して保存する
5. 楽曲詳細またはリリース詳細で、関連情報を確認する

## UI Notes

- 第1回は `admin` 優先で進める
- `Media` は楽曲作成 / 編集画面の中で扱う
- `Media` UI は `既存 Media 検索` と `新規 Media 追加フォーム` の 2 段構成を基本とする
- リリースは独立画面として持つ
- 楽曲詳細は現行の表示をベースにし、追加差分は `Media` と `Release` に絞る

## API / Data Notes

- 既存の `Song` / `Person` / `Performer` / `SongTag` 基盤を前提にする
- `Song` の第1回スコープで重要な属性は `タイトル / 説明 / 種別 / タグ / 表示有無 / 歌詞リンク`
- `Release` は独立エンティティとして持つ
- 第1回で扱う `Release` の最小モデルは `タイトル / 種別 / 流通形態 / 発売日 / 説明 / 表示有無`
- 初期の `Release` 種別は `single / album / ep / other` とする
- `distributionTypes` は複数値で持ち、初期値は `digital / physical / limited / other` とする
- `ReleaseSongLink` は関係エンティティとして持ち、第1回では `release_id / song_id / track_no` を中心に扱う
- `歌詞リンク` は `Song` の補助属性として持ち、未設定を許容する
- 作詞者 / 作曲者 / 編曲者は `Person` との重要な関連だが、未設定を許容する
- `Media` は独立エンティティとして持つ
- `Media` は概念上、楽曲にも出来事にも紐づきうる外部参照リソースとして扱う
- 第1回で扱う `Media` の運用対象は、楽曲に直接関連する公式メディアのみに限定する
- `Media` の最小モデルは `タイトル / URL / MediaType / MediaFormat / 表示有無`
- 初期の `MediaType` は `video / article / social_post / official_page / other` とする
- 初期の `MediaFormat` は `mv / audio_video / stream_archive / short_video / live_clip / other` とする
- Phase 1 では `MediaType` は実質 `video` を中心に扱い、`MediaFormat` で動画の意味分類を表現する
- `SongMediaLink` は関係エンティティとして持ち、第1回では `song_id / media_id / order_no` を中心に扱う
- 同一アーカイブを複数楽曲に結び付けることを許容する
- 楽曲ごとに参照箇所を分けたい場合は、タイムスタンプ込み URL を持つ別 `Media` として扱う
- 将来の `Event` は、ライブや配信に限らず、ヰ世界情緒が関わった出来事全般を扱う想定とする
- 将来の `Performance` は、楽曲がある出来事で披露された事実を表す独立の関係として扱う

## Acceptance Criteria

- 管理者が楽曲を `タイトル / 説明 / 種別 / タグ / 表示有無 / 歌詞リンク` とともに登録 / 編集できる
- 管理者がリリースを `タイトル / 種別 / 流通形態 / 発売日 / 説明 / 表示有無` とともに登録 / 編集できる
- 作詞者 / 作曲者 / 編曲者は未設定のままでも楽曲を保存できる
- 管理者が事前登録されたタグだけを楽曲へ紐づけられる
- 管理者がリリースに収録楽曲を紐づけ、曲順を管理できる
- 管理者が楽曲作成 / 編集画面で既存 `Media` を検索して紐づけられる
- 管理者が楽曲作成 / 編集画面で新規 `Media` を作成し、そのまま楽曲へ紐づけられる
- 管理者が楽曲に紐づく `Media` を並び替えできる
- 管理画面の楽曲詳細で、既存表示情報に加えて関連 `Media` と所属 `Release` を確認できる
- 管理画面のリリース詳細で、収録楽曲を確認できる
- `Media` は公式の楽曲関連メディアだけを対象にする
- `Media` が存在しない楽曲も登録 / 保存できる
